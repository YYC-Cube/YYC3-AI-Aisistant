### 3.2 需要改进的方面 ⚠️

| 编号 | 问题 | 位置 | 严重程度 | 建议 |
|------|------|------|----------|------|
| W-01 | 项目目录扁平化 | 根目录 | 中 | 将 components/hooks/services 移入 src/ |

| W-03 | DevOpsService 过大 | services/DevOpsService.ts (1675行) | 中 | 按职责拆分 MCP/Workflow/Health |
| W-04 | Mock 数据硬编码 | services/GitHubService.ts | 低 | 抽取为 fixtures 文件 |
| W-05 | ESLint 13 warnings | 多文件 | 低 | 修复 missing dependency 警告 |
| W-06 | 测试覆盖率有限 | hooks/__tests__/ | 中 | 仅覆盖 2 个 Hook，需扩展到组件/服务层 |
| W-07 | 缺少 ErrorBoundary | App.tsx | 中 | 添加全局错误边界组件 |
| W-08 | Supabase CORS 全开 | supabase/functions/ | 高 | 生产环境需限制 origin: "*" |
| W-09 | 无 git history | .git/ | 中 | 需初始化 git 并关联远程仓库 |
| W-10 | 缺少 .env.example | 根目录 | 低 | 创建环境变量模板文件 |

### 3.3 存在风险的问题 🔴

| 编号 | 风险 | 位置 | 影响 | 缓解措施 |
|------|------|------|------|----------|
| R-01 | Supabase Edge Function CORS `origin: "*"` | supabase/functions/server/index.tsx | CSRF 攻击风险 | 限制为已知域名白名单 |
| R-02 | GitHub Token 硬编码风险 | services/GitHubService.ts (mock) | 信息泄露 | 确保 mock 数据不含真实 token |
| R-03 | 无数据库迁移工具 | docs/postgresql-15-schema.sql | Schema 变更管理困难 | 引入 dbmate 或 Prisma Migrate |
| R-04 | 无速率限制（前端直连 API） | vite.config.ts proxy | API 滥用风险 | 服务端添加 rate limiting 中间件 |
